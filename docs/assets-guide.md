# Правила хранения ресурсов

## Общие и сценические материалы

Общие ресурсы персонажей хранятся в `characters/<id>/`, предметов —
в `props/<id>/`. Сцены находятся в `episodes/<epNN>/scenes/<scNN>/` и ссылаются
на общие ресурсы по относительным путям. Не дублировать файлы персонажей,
предметов или библиотек действий в папках сцен.

Персонажи: `uki` — Үкі, `kirpi` — Кірпі. Предметы: `book`, `bow`, `arrow`,
`lamp`. Новые идентификаторы добавляются по мере появления реальных материалов.
Пустые каталоги с `.gitkeep` обозначают только место будущего хранения.

## Имена и версии

- Для новых рабочих файлов использовать латиницу в нижнем регистре, цифры
  и подчёркивания, без пробелов: `<id>_<role>_vNNN.<ext>`.
- Эпизоды именовать `ep01`, `ep02`, сцены — по сюжетному номеру `scNN`.
  Для EP01 закреплены **sc00–sc15**: 00 — отдельное вступление,
  01 — чтение, 04 — закрыть и положить книгу. Порядок технической разработки
  не задаёт нумерацию; первой для wing rig выбрана 04.
- Для кадров добавлять номер с одинаковой шириной:
  `ep01_sc01_storyboard_v001_f0001.png`. Номер исходной страницы и номер
  кадра анимации указывать раздельно в описании.
- Для версий использовать `v001`, `v002` и далее; связанным экспортам указывать
  версию исходника. Новую редакцию сохранять отдельно, не перезаписывая оригинал.
- Существующие оригиналы сохранять с исходными именами. При коллизии имён
  размещать их в отдельных каталогах импорта с описанием происхождения.

Примеры имён (это соглашения, а не существующие файлы):
`uki_body_v001.kra`, `uki_wing_left_v001.png`, `uki_rig_v001.blend`,
`uki_take_book_v001.blend`, `book_art_v001.kra`, `ep01_sc01_v001.blend`.

## Форматы и размещение

| Материал | Формат и каталог | Правило |
| --- | --- | --- |
| Текстовая раскадровка EP01 | `episodes/ep01/storyboard/uki_kirpi_storyboard_v1.md` | Неизменённый источник 01–15; дополнение 00 — отдельно в `scene-00-intro.md` |
| Раскадровка, оригиналы | Реальные исходные форматы, включая `.kra`, в `episodes/ep01/storyboard/originals/` | Сохранять без изменений |
| Выбранные кадры | PNG в `episodes/ep01/storyboard/selected-frames/` | Указывать оригинал и страницу/слой |
| Исходники персонажа | `.kra` в `characters/<id>/krita/` | Сохранять слои и авторскую структуру |
| Текстуры персонажа | PNG в `characters/<id>/textures/` | Сохранять прозрачность и параметры экспорта |
| Rig | `.blend` в `characters/<id>/rigs/` | Указывать совместимость и ссылки на текстуры |
| Actions | `.blend` в `characters/<id>/actions/` | Указывать имена Actions и версию rig |
| Предметы | `.kra`, PNG, `.blend` в `props/<id>/` | При росте объёма использовать подпапки и описать их |
| Сцена | `.blend` в `episodes/<epNN>/scenes/<scNN>/` | Подключать общие ресурсы по относительным путям |
| Звук и монтаж | Реальные материалы в `audio/`, проекты монтажа в `edit/` эпизода | Указывать источники и использованные версии |
| Результаты и кеши | `output/` | Локальные, в Git не включаются |

Намеренно сохраняемые `.kra`, `.blend`, PNG и документация не исключаются
из Git. Резервные копии приложений, автосохранения и временные экспорты не
являются утверждёнными версиями ресурса. В `output/` отслеживается только
`.gitkeep`, чтобы каталог появился при клонировании.

## Кадры и параметры изображения

До экспорта и анимации согласовать параметры для конкретной сцены и записать
их в её локальный `README.md`: разрешение в пикселях, FPS, начало и конец
диапазона кадров (обе границы включены). Длительность должна соответствовать
числу кадров и FPS. Универсальные значения для всего проекта пока не назначены.
Для EP01 формат раскадровки — **1920×1080, 16:9**, рабочий аниматик исходных
**01–15 — 36 секунд, 24 FPS**. Длительность 00 и общий новый хронометраж —
`TBD`; не выводить длительности отдельных планов из общей суммы.

Для PNG записать размеры холста, цветовой профиль, наличие альфа-канала и
связь со слоем `.kra`. Части одного персонажа экспортировать с согласованными
холстом и точкой привязки; обрезку и смещение явно описывать. Не менять масштаб,
профиль, FPS или нумерацию кадров автоматически.

## Происхождение и сохранность исходников

Рядом с добавляемыми материалами создать локальный `README.md` и заполнить
фактические сведения:

- Идентификатор, назначение и версия ресурса.
- Автор/правообладатель, источник (путь, ссылка или переданный оригинал), дата
  получения и исходное имя. Для производного файла — точный исходник и его версия.
- Версия Krita/Blender, параметры экспорта или сохранения; для выбранного кадра —
  страница/слой/номер в оригинале, для Actions — совместимый rig и диапазон кадров.
- Подтверждённые условия использования и ссылка на разрешение либо явная отметка,
  что условия ещё не утверждены.

Исходники не изменяются автоматически. Импорт, экспорт, нормализация имён и
будущие инструменты не должны перезаписывать оригиналы. Для изменения исходника
нужно отдельное явное решение; рабочую копию или новую версию сохраняют отдельно,
с указанием связи с оригиналом. Перемещение или переименование общего ресурса
требует проверки зависимых сцен.

Авторский Markdown EP01 импортирован без изменений, его происхождение и
зависимости указаны в [README раскадровки](../episodes/ep01/storyboard/README.md),
а порядок сцен — в [реестре](../episodes/ep01/scenes.md).
Художественные оригиналы добавляются отдельно. Пока их нет, изображения,
модели, звук, rig и сцены не выдумываются. Сгенерированные материалы не заменяют оригиналы.

## Права и лицензии

Лицензии на код и художественные ресурсы определяются **раздельно**.
Для каждой категории требуется отдельное утверждение правообладателями.
На этапе M0.1 лицензии не назначены: автоматически применять CC0, MIT,
CC BY-NC-SA или другую лицензию нельзя. Существующие сведения об авторстве и
лицензиях импортируемых материалов сохраняются; неясные условия отмечаются
явно и не считаются разрешением на использование.
