# Производственный процесс

Последовательность: storyboard → аниматик → layout/черновые позы → rough
animation → промежуточные кадры → clean-up/цвет → композитинг → монтаж.
Krita **6** — рисунки и покадровая анимация; Blender при необходимости —
rig/Actions, камера и композитинг. Монтаж — Kdenlive или согласованный редактор,
экспорт — FFmpeg. Эксперимент движения книги относится к #11; подготовка
#7/#10 его не заменяет.

## 1. Получение ресурсов

Google Drive хранит бинарные исходники и производные файлы. GitHub — код,
Markdown и [манифест](../assets/manifest.yaml). Перед работой:

```bash
.venv/bin/python -m pipeline.assets sync --episode ep01 --credentials .secrets/drive-user.json
.venv/bin/python -m pipeline.assets verify --episode ep01
```

[Установка и авторизация](../assets/README.md). Локальные файлы находятся
в `.local-assets/`, временные результаты — `output/`. В Git/Git LFS бинарные
материалы не добавляются. Исходники не перезаписываются автоматически,
новые версии регистрируются отдельно после проверки и сохранения истории.

## 2. Storyboard и аниматик

[Оригинальный Markdown](../episodes/ep01/storyboard/uki_kirpi_storyboard_v1.md)
содержит **15 кадров 01–15**, а [вступление 00](../episodes/ep01/storyboard/scene-00-intro.md)
хранится отдельно. [Реестр](../episodes/ep01/scenes.md) описывает **16 планов
00–15**. Текст не редактировать ради путей к графике. Художественный storyboard
и выбранные кадры — Drive/манифест, локально
`.local-assets/episodes/ep01/storyboard/`. Недостающие оригиналы генерациями
не подменять.

Исходные **01–15 — 36 секунд, 24 FPS**, формат **1920×1080, 16:9**.
План, камера и длительность 00, новый общий хронометраж — `TBD`.
Не распределять 36 секунд на 16 сцен. Детальный тайминг указан среди
[ожидаемых зависимостей](../episodes/ep01/storyboard/README.md).

## 3. Референсы и черновое движение

[Пять принятых статичных поз Үкі](../characters/uki/references/poses/README.md)
служат референсами всей пластики персонажа. KRA v7 не изменять.
Сначала проверять ритм и движение упрощёнными позами, затем детализировать
перья. Разрешённые кисти — **Bristles-5 Flat** и **Dry Bristles**; установка
и результат проверки в Krita 6 описаны в README поз.

Связанный набор с книгой: **00 take/open → 01 read → 04 close/place**.
04 выбрана первой для технической разработки, сюжетный порядок сохраняется.
Материалы 00/04 получить по #9, отдельно учитывать KRA и первичные генерации.
Количество/порядок кадров фиксировать по реальным файлам. Крылья — одна
из частей общей пластики персонажа.

## 4. Экспорты, rig и Actions при необходимости

Экспорт PNG создаёт производный файл, сохраняя исходный KRA.
Место — `.local-assets/characters/<id>/exports/<version>/`, отдельно от
первичных генераций. Записать исходный ID/версию, профиль, прозрачность,
холст, смещения, имена слоёв. Для переноса на другую машину сохранить
на Drive и зарегистрировать; в GitHub экспорты не коммитить.

Общие rig/Actions — `.local-assets/characters/<id>/{rigs,actions}/`.
Указать версии Blender/rig, имена Actions, диапазоны и FPS. Link / Library
Overrides и относительные ссылки на текстуры должны работать после sync.
Общие файлы не копировать по сценам. Blender MCP и создание rig — отдельная работа.

## 5. Сцены и render

Git-каталоги `episodes/ep01/scenes/scXX/` содержат документацию и ссылки
на манифест. Рабочие `.blend` — `.local-assets/episodes/ep01/scXX/`.
До анимации записать FPS, разрешение, диапазон и версии зависимостей.
Перед Blender-сборкой повторить `verify`; ссылки — относительные внутри клона,
без домашнего пути пользователя.

Рендер — `output/ep01/scXX/<version>/`, вместе с параметрами и диагностикой.
Будущие инструменты — `pipeline/blender/`, `pipeline/render/`. Успешность
первого тестового рендера подтверждается реальным результатом, не каталогами.

## 6. Монтаж и передача

Звук и проекты монтажа — `.local-assets/episodes/ep01/{audio,edit}/`,
экспорты — `output/ep01/edit/`. Указать версии кадров/звука, проверить паузы
и финальную круглую диафрагму вокруг неподвижной Үкі. Долговременные результаты
сохранить на Drive и зарегистрировать.

Перед передачей проверить происхождение/права, версии, хеши, параметры кадров
и относительные ссылки. `git status` не должен содержать бинарные ассеты,
credentials или рендеры. Лицензии кода и графики утверждаются раздельно.
