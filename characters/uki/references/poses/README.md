# Пять принятых статичных референсов Үкі

Автор — **Андрей Свининых**. Исходник `uki_five_views_brush_cleanup_v7.kra`,
версия **v7**, проверена **27.10.2026**. Запись **`uki.poses.v7`** в
[манифесте](../../../../assets/manifest.yaml) содержит реальный Drive ID,
локальный путь, размер и рассчитанный SHA-256. Локальная копия —
`.local-assets/characters/uki/poses/`; KRA/PNG не хранятся в GitHub.

Референсы охватывают **всю пластику персонажа**: силуэт, пропорции, тело,
голову, крылья, лапы, глаза, характер, выразительность и будущие переходы
между позами. Группы 01–05 — ракурсы, не сюжетные сцены EP01.

## Проверка исходника в Krita 6

Оригинал получен через авторизованный Drive connector: **3 270 260 байт**.
ZIP/CRC и XML проверены; UTF-8 и казахские символы сохранены.
SHA-256: `91e1ad07a4e980f903f4af432bdf157332be799b88f028c3597ba262db1c5340`.

Открыт в **Krita 6.0.4.1 (git bd6e8d0)** через `~/.local/bin/krita6`.
Для проекта использовать Krita 6: `/usr/bin/krita` — другая установленная версия.
Параметры подтверждены приложением: **440×560, RGBA/U8**,
`sRGB-elle-V2-srgbtrc.icc`, **120 DPI**. Настройка 24 FPS внутри KRA не означает
готовой анимации или утверждения частоты кадров эпизода.

Верхних групп ровно пять, в порядке docker сверху вниз:

1. `05 — Тело в профиль · голова к зрителю на 90°`.
2. `01 — Анфас`.
3. `02 — Три четверти`.
4. `03 — Профиль`.
5. `04 — Сзади`.

При открытии виден только анфас; остальные группы скрыты. Все пять отдельно
просмотрены через проекции слоёв в Krita, без изменения видимости или сохранения
документа. Изображения соответствуют перечисленным ракурсам. После проверки
`modified: false`, SHA-256 файла совпадает с исходным.

В 01/02/04 находятся сохранённая основа и две группы доработки плеч; в 03 —
основа и доработка видимого плеча. Доработки содержат синюю основу, форму
и перекрытия перьев, сухие блики/волокна и маску границы силуэта.
Группа **05** содержит:

- `Голова анфас — поворот относительно тела 90°` — отдельный paint layer.
- `Стык шеи — две согласованные кисти` — переход под щекой, светлые кончики
  перьев и маска `Только шейное оперение`.
- `Тело профиля — исходные координаты, неподвижно` — заблокированный paint layer.

Статус «принят» дан автором в задаче; техническая проверка его не назначает.

## Две разрешённые кисти

| Пресет | Ресурс в архиве | Наконечники | ID манифеста |
| --- | --- | --- | --- |
| `f) Bristles-5 Flat` | `resources/paintoppresets/f)_Bristles-5_Flat.kpp` | `rake_flat.png` | `krita.brush.bristles-5-flat` |
| `g) Dry Bristles` | `resources/paintoppresets/g)_Dry_Bristles.kpp` | `scratches_rough.gih`, `abominable_snowman.png` | `krita.brush.dry-bristles` |

Наконечники — в `resources/brushes/`. Исправленный Dry ZIP (396 833 байта)
содержит только пресет Dry. `rake_flat.png` также есть в обоих ZIP с одинаковым
хешем и установлен один раз. Проверены CRC и все элементы `SHA256SUMS`.
Происхождение сохранено в `resources/provenance.json` и
`resources/source_bundle_meta.xml`: `Krita_4_Default_Resources.bundle`,
в metadata комплекта указана `CC-0`. Это сведения источника кистей,
не лицензия персонажа или кода проекта.

В пользовательском каталоге нужных файлов не было. Установлены два KPP
и три наконечника в `~/.local/share/krita/{paintoppresets,brushes}/`,
с оригинальными именами. Системные ресурсы не заменялись.
После запуска **Krita 6.0.4.1** оба точных имени пресетов и три наконечника
найдены через API resource registry; изображения загружаются
(`image().isNull() == false`). XML пресетов указывает наконечники из таблицы.
Исходный KRA не изменялся; тестовые штрихи на нём не рисовались.

Повторная настройка после загрузки ресурсов:

```bash
.venv/bin/python -m pipeline.krita.install_brushes
.venv/bin/python -m pipeline.krita.install_brushes --install
~/.local/bin/krita6 .local-assets/characters/uki/poses/uki_five_views_brush_cleanup_v7.kra
```

Без `--install` команда только проверяет/показывает действия. С ним записывает
отсутствующие файлы, одинаковые пропускает, отличающиеся локальные ресурсы
сохраняет с ошибкой. Закрыть Krita перед установкой и запустить заново после.
Если в настройках задан иной каталог, передать `--resource-dir /путь/к/ресурсам`;
по умолчанию учитывается `XDG_DATA_HOME`.
[Устройство ресурсов Krita](https://docs.krita.org/en/reference_manual/resource_management.html).

Другие кисти, в том числе присутствующая `Dry Bristles Eroded`, рабочими
не назначены. Все бинарные ресурсы кистей остаются вне GitHub.
