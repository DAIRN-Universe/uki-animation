# Үкі — uki-animation

Производственный проект мультфильмов «Үкі». Автор — **Андрей Свининых**.
Персонажи: Үкі (сова, `uki`) и Кірпі (ёж, `kirpi`). Рисунки и покадровая
анимация — **Krita 6**, Blender — при необходимости для rig, Actions,
движения и композитинга; монтаж — Kdenlive/согласованный редактор, экспорт FFmpeg.
Код и документация — IntelliJ IDEA, Codex и Git на Linux.

## Получение ресурсов

**Все бинарные художественные файлы хранятся на Google Drive.**
KRA, исходные/сгенерированные/экспортированные PNG, Blender-файлы, кисти,
звук и видео не коммитятся в GitHub и Git LFS. В Git — код, Markdown,
конфигурации и [манифест ресурсов](assets/manifest.yaml).
Локальные файлы — игнорируемый `.local-assets/`, результаты — `output/`.
Это правило распространяется на картинки README; публичные ссылки требуют
проверки доступа и решения автора.

Linux, Python 3.10+. Команды из корня проекта:

```bash
python3 -m venv .venv
.venv/bin/python -m pip install -r requirements-assets.txt
.venv/bin/python -m pipeline.assets list
.venv/bin/python -m pipeline.assets sync --character uki --credentials .secrets/drive-user.json
.venv/bin/python -m pipeline.assets verify --character uki
.venv/bin/python -m pipeline.krita.install_brushes
```

[Авторизация, фильтры, схема и сохранность](assets/README.md).
Credentials/token хранятся только локально, не попадают в Git и логи.
Повторный sync сверяет SHA-256 и сохраняет локальные изменения при ошибке.
Новые версии регистрируются отдельно; исходники автоматически не изменяются.
Для записи кистей добавить `--install`, после чего запустить заново **Krita 6**.
На текущем компьютере её launcher — `~/.local/bin/krita6`; системный
`/usr/bin/krita` ведёт к другой версии.

## Навигация

| Путь в Git | Содержание |
| --- | --- |
| `assets/` | Манифест Drive-ресурсов, схема и команды синхронизации |
| `characters/uki/` | Документация Үкі и пяти принятых поз |
| `characters/kirpi/` | Логические разделы будущих материалов Кірпі |
| `props/` | Логические разделы `book`, `bow`, `arrow`, `lamp` |
| `episodes/ep01/scenes.md` | Реестр 00–15: план, действие, камера, источник |
| `episodes/ep01/storyboard/` | Авторский Markdown 01–15, дополнение 00 и происхождение |
| `episodes/ep01/scenes/sc00/` … `sc15/` | Места для текстовых описаний и ссылок на манифест |
| `episodes/ep01/audio/`, `edit/` | Логические разделы звука/монтажа, не бинарные материалы в Git |
| `pipeline/` | Asset Sync, установка кистей; места будущих Blender/render-инструментов |
| `tests/` | Проверки без внешней сети |
| `docs/` | [Правила ресурсов](docs/assets-guide.md), [процесс производства](docs/production-pipeline.md) |

Первоначальные пустые каталоги с `.gitkeep` остаются логическими разделами.
Они не означают готовых ресурсов и не являются местом скачивания бинарных
файлов. Не создавать новые Git-каталоги для скачиваемых материалов.

Примеры локального размещения (кроме поз и кистей — будущие пути):

```text
.local-assets/
├── characters/<id>/{poses,krita,exports,rigs,actions}/
├── props/<id>/
├── tools/krita/brushes/
└── episodes/ep01/{storyboard,sc00,sc04,audio,edit}/
output/ep01/<scene>/<version>/
```

## Добавление материалов

1. Свериться с правилами ресурсов, storyboard и сюжетной нумерацией.
2. Сохранить реальный оригинал на Drive, проверить метаданные и происхождение.
3. Получить файл, проверить содержимое, вычислить SHA-256; зарегистрировать
   ID, версию, путь, размер, назначение, статус и права в манифесте.
4. Общие ресурсы не дублировать по сценам. Для производных экспортов записывать
   исходный ID/версию и настройки; оригинал не перезаписывать.
5. До Blender-сборки выполнить `verify`; зависимости подключать относительными
   путями внутри клона. Художественные оригиналы без отдельного решения не менять.
6. Перед коммитом проверить `git status`: бинарные ассеты, credentials,
   кеши и `output/` не должны быть добавлены. Изменения — через PR для проверки.

Не придумывать отсутствующие изображения, ссылки, хеши, модели и звуки.
Пустые каталоги не означают готовности. Настройка Blender MCP, rig,
анимация и первый тестовый рендер — отдельные работы.

## Проверки и права

```bash
.venv/bin/python -m unittest discover -s tests -v
.venv/bin/python -m pipeline.assets verify --character uki
```

Проект открывается в IDEA через **File → Open**, локальные настройки IDE
игнорируются. Версии Krita/Blender и параметры экспорта записываются при
добавлении материалов. Лицензии кода и художественных ресурсов определяются
**раздельно**, пока автоматически не назначены. Публикация не разрешает
повторное использование; сохранять сведения об авторах и исходных лицензиях.
